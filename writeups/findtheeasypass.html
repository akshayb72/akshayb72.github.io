Find The Easy Pass

HTB Reverse Engineering Challenges Very Easy Find The Easy Pass June 2026
01 / execute

Initial Execution

The challenge zip contains a Windows PE (portable executable). Run it with Wine on Linux or inside a Windows VM. A small GUI dialog appears asking for a password. Type anything wrong and it shows an "Easypass — Wrong Password!" message box and exits.

Setup note If you're on Linux, wine EasyPass.exe works fine. On Windows, just double-click. Either way, keep the program open alongside your debugger — you'll need to attach to the running process later.
02 / recon

Static Recon — strings

Before reaching for a debugger, try the cheapest tool first: strings. It dumps all printable text sequences from the binary. On SpookyPass-style challenges this immediately reveals a hardcoded password — but not here. 

C:\> strings EasyPass.exe
This program must be run under Win32
CODE
`DATA
.idata
.tls
.rdata
Boolean  False  True  Char  Integer  Byte
Word  Cardinal  String  TObject  TObject
System  IInterface  System  TInterfacedObject
uYhD  YZ^[

The output is mostly Delphi/Pascal runtime internals — no password string in sight. The presence of Delphi type names (TObject, TInterfacedObject) tells us the binary was compiled with Delphi or Free Pascal. Delphi encodes strings differently from C, which is why strings misses them. Time to use a debugger.

Why strings failed Delphi stores short strings with a length-prefix byte rather than a null terminator. The strings tool looks for runs of printable ASCII ending in \0, so length-prefixed strings are invisible to it.
03 / debug

Dynamic Analysis — x32dbg

The binary is 32-bit (the Win32 string in the PE header confirms it), so open it in x32dbg. x32dbg is a free, open-source Windows debugger purpose-built for 32-bit reversing. Load the file via File → Open.

Why x32dbg? Use x32dbg for 32-bit PE files and x64dbg for 64-bit. They look identical but the pointer width differs. Loading a 32-bit binary in the 64-bit variant will still work, but x32dbg gives cleaner register views for 32-bit code.

Once loaded, right-click anywhere in the disassembly pane and navigate to Search for → All Modules → String references. In the search bar type Wrong Password! — the exact text from the dialog box. 

Address      Disassembly                    String
00454144     mov eax, easypass.454200       "Wrong Password!"

Only one result appears. Double-click it. x32dbg jumps to that address in the disassembly and you can see the surrounding code: a conditional jump leads either to the "Wrong Password!" path or to a "Good Job. Congratulations" success path.

04 / breakpoint

Setting Breakpoints & Catching the Comparison

Scroll up a little from the "Wrong Password!" address. You'll see a call instruction a few lines above the conditional jump — that's the string-comparison function. There are also two mov instructions that load values into EAX and EDX just before the call. Set a breakpoint on that call line by pressing F2 (the line turns red).

Now press F9 (Run). The program's GUI appears. Type any dummy password (e.g. 1234) and click "Check Password". The debugger immediately breaks at your breakpoint. Look at the registers panel on the right side: 

EAX   02011D34   "1234"       ← your input
EDX   02013994   "f******"   ← the correct password
EBX   02011E44
EBP   0019F2FC
...

The comparison function takes two arguments: EAX (user input) and EDX (expected password). EDX contains the plaintext password sitting in memory — we didn't even need to patch the binary.

Takeaway

Key Takeaway

When strings returns nothing useful, check the compiler. Delphi, VB6, and .NET all have string encodings that bypass the standard tool. Dynamic analysis is the next move: set a breakpoint near the failure message, run to it, and inspect the registers — the plaintext password is almost always sitting in a register right before the comparison call.

Escalation order for GUI crackmes file → strings → identify compiler/runtime → load in debugger → find error string → set breakpoint on comparison → run and inspect registers → patch or reuse recovered value
