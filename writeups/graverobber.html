Graverobber

HTB Reverse Engineering Challenges Very Easy Graverobber Jun 2025
01 / execute

Initial Execution

Run the binary to see what it does. It immediately exits with a single error message — no prompt, no input required. 

$ ./robber
We took a wrong turning!
Observation The binary exits with code 1 and prints an error. No interesting strings are visible with strings — the flag isn't stored in plaintext. Time to look at what the binary is actually doing at the syscall level.
02 / strace

Tracing with strace

strace intercepts and records every system call the process makes. Running the binary under it reveals what it's looking for before it exits. 

$ strace ./robber
execve("./robber", ["./robber"], 0x7ffe7e76ff20) = 0
...
newfstatat(AT_FDCWD, "H/", 0x7ffcbd70cf50, 0) = -1 ENOENT (No such file or directory)
write(1, "We took a wrong turning!\n", 25) = 25
exit_group(1)
+++ exited with 1 +++

The binary calls newfstatat — a syscall that checks whether a file or directory exists — on the path H/. Since that directory doesn't exist, it gets ENOENT and exits. The directory name H is the first character of the flag.

newfstatat is a variant of stat that checks file metadata. A return of -1 ENOENT means the path does not exist. The binary uses this as a gating mechanism — it only continues if the expected directory tree is present.
03 / discovery

Discovering the Pattern

Create the directory H and run strace again. The binary gets past the first check and immediately looks for the next directory. 

$ mkdir H && strace ./robber
...
newfstatat(AT_FDCWD, "H/", {st_mode=S_IFDIR|0755, ...}, 0) = 0
newfstatat(AT_FDCWD, "H/T/", 0x7fff03f91e00, 0) = -1 ENOENT (No such file or directory)
write(1, "We took a wrong turning!\n", 25) = 25
exit_group(1)

Now it looks for H/T/. The binary encodes the flag as a sequence of nested directories — each character of the flag is a directory name, nested inside the previous one. Creating them manually would take forever. We need a script.

04 / scripting

Automating with Python

The script runs the binary under strace in a loop, reads the last newfstatat call to find which directory is expected next, creates it, and repeats until the binary stops printing the error message. 


import os
import shutil
from pwn import *

# removes previous dirs and creates new ones
if os.path.exists("directories"):
    shutil.rmtree("directories")
os.mkdir("directories")
os.chdir("directories")

while True:
    with context.local(log_level='ERROR'):
        p = process(["strace", "-e", "newfstatat", "../robber"])
        out = p.recvall().decode()
        p.close()

    if 'wrong turning' not in out:
        break

    stats = [line for line in out.split("\n") if "newfstatat" in line]

    flag = ""

    path = stats[-1].split('"')[1]

    flag += path.replace("/", "")

    os.makedirs(path, exist_ok=True)

print(flag)
Why exist_ok=True Without it, os.makedirs raises an error if the directory already exists — which happens on any re-run of the script. The flag on this initial fix prevents a crash between iterations.
05 / flag

Getting the Flag

Run the script. It prints each directory character as it creates it, spelling out the flag letter by letter until the binary exits cleanly. 

$ python flag.py
HTB{...}
✓

Flag captured. Each directory name was one character of the flag. The binary used newfstatat to spell out the flag one level at a time — the script reconstructed it by reading the last failing syscall on each iteration.

Takeaway

Key Takeaway

When strings gives nothing useful, strace is the next tool to reach for. A binary that checks for files or directories is leaking its logic through syscalls — you can read its expectations directly from the trace without ever disassembling it.
