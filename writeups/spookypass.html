SpookyPass

HTB Reverse Engineering Challenges Very Easy SpookyPass June 2025
01 / execute

Initial Execution

First, run the binary inside a VM to observe its behaviour. It prints a welcome message and prompts for a password. Any wrong input causes it to exit immediately. 

$ ./pass
Welcome to the SPOOKIEST party of the year.
Before we let you in, you'll need to give us the password:
You're not a real ghost; clear off!
Observation The binary reads from stdin via fgets, compares the input against a hardcoded value, then branches on the result. Classic crackme pattern.
02 / analysis

Static Analysis — strings

Before pulling out a disassembler, try the simplest approach: dump all printable strings from the binary. Hardcoded passwords are often stored in plaintext inside the .rodata section. 

$ strings pass
/lib64/ld-linux-x86-64.so.2
fgets
stdin
puts
__stack_chk_fail
...
s3cr3t_p455_f0r_gh05t5_4nd_gh0ul5
Welcome to the SPOOKIEST party of the year.
Before we let you in, you'll need to give us the password:
Welcome inside!

The password is stored unobfuscated in the binary — no XOR encoding, no hashing. The string s3cr3t_p455_f0r_gh05t5_4nd_gh0ul5 stands out immediately among the standard libc imports.

03 / flag

Submitting the Password

Feed the recovered string as input to the binary.

$ ./pass
Welcome to the SPOOKIEST party of the year.
Before we let you in, you'll need to give us the password: s3cr3t_p455_f0r_gh05t5_4nd_gh0ul5
Welcome inside!
HTB{...}
✓

Flag captured. Password comparison succeeded — branch taken to win condition.

Takeaway

Key Takeaway

Always start with the lowest-cost recon. strings + file + ltrace resolve a significant portion of easy reversing challenges before a disassembler is ever needed. Match your tool complexity to the resistance of the target.

Escalation order for easy crackmes file → strings → ltrace / strace → disassembly (Ghidra / radare2) → dynamic debugging (GDB / pwndbg)
